# 指标与时间口径

## Token 与费用

每条事件使用四个互不重叠的字段：`input`（非缓存输入）、`output`、`cache_read`、`cache_write`。所有统计 API 的行新增 `tokens`，等于四项之和；保留原字段。推理 Token 已包含于输出时不额外累加。

估算费用为四项分别乘以 `prices.json` 对应单价再除以一百万。Codex 原始 `input_tokens` 含缓存，入库前扣除缓存读写。例如输入 1,000,000、其中缓存读取 800,000，输入 $2/M、缓存读取 $0.2/M 时：`200000 × 2/M + 800000 × 0.2/M = $0.56`。不是把 1,000,000 全按输入单价计价再加缓存。

来源自带的实际费用优先，包括明确的零费用。`cost_source` 区分价格表估算、来源提供的估算/实际费用、迁移重算等。旧 Codex 费用按升级时价格表重算，**不是历史官方账单**。官方累计成本首次出现或来源变更时，无法定位时间的费用校准单独保留，不伪装成当天调用费用。

## 三种时间质量

| time_quality | 含义 | 全部历史 | 指定范围 / 趋势 |
|---|---|---|---|
| `exact` | 日志有事件时间 | 计入 | 按事件时间计入 |
| `observed` | 两次累计快照间的差量，区间为 `interval_start` 至 `ts` | 计入，标记估算 | 只有整个区间落在范围或同一分桶时才计入 |
| `unallocated` | 存量无法还原时间，或历史费用校准 | 计入 | 不作为精确用量计入，单独报告 |

观察区间只是“这段时间内发生了变化”，不是逐次请求的准确时间。没有变化的扫描也更新观察边界。累计计数器下降时记录重置，保存旧总量、更新基线；下一轮只计算新基线后的增量。

例如昨天首次观察到累计 1,000，今天 10:00 再次观察仍为 1,000，11:00 变为 1,100：全部历史 1,100，今天 100（观察区间估算），另有 1,000 未分配历史。如果只有昨天与今天两次观察，新增 100 跨日，不声称全部发生在今天，而是在未分配摘要中说明。

一个跨小时但不跨日的区间可以计入当天总量，却不能任意计入某个小时。趋势之和因此可能小于统计总量；界面会显示排除的用量。

## API 兼容与展示

- `/api/stats`：原 `rows`、`total` 保留；每行包含 `tokens`、`cache_write`、`estimated_tokens`、`unallocated_tokens`。`total.unallocated={tokens,cost,events}` 是当前时间口径无法归入的摘要。
- `/api/daily`：保留 `rows`，新增 `summary`（含 `unallocated`、`estimated_tokens`）；今天按小时，其余按天。
- `/api/models`、`/api/sessions`：统一总 Token 与时间质量计数。纯未分配会话的 `ts`、`last_seen` 可为空，不能解释成 1970 年或今天。
- `/api/session_detail`：显示会话全部历史，并返回 `observation_intervals`；与范围筛选后的列表总量可能不同，界面明确标注。
- `/api/quotas`：窗口保留 `source`，新增 `stale`；本地窗口 `unallocated` 为同 `unit` 的未分配用量，不包含在 `used` / `pct`。用户 `include_cache` 配置保持不变，启用时计入缓存读与写。
- `/api/scan/status`：`running`、`last` 保留；最近一次扫描有 `source`、`started_at`、`finished_at`（Unix 秒）及各工具结果/错误。重置与无法映射的旧来源会在扫描结果中报告。

限定范围的未分配摘要包含“可能属于此范围、但不能确定”的历史，不代表这些用量一定发生在这个范围内。所有界面和状态栏使用后端 `tokens`，避免各自重新计算而漏加缓存。

## 时间范围口径

- 今天：自然日 0 点起。
- **本周：最近 7 天滚动**（非周一到周日），因此在月初会出现「本周 > 本月」——
  本周包含上月末的几天，属于正常口径。界面在时间范围选择器下直接标注实际日期区间。
- 本月：自然月 1 日 0 点起。
- 全部：全部历史（含未分配到时间的量）。

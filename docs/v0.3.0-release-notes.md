# TokenTracker v0.3.0

## 简体中文

本地优先的可信统计、项目分析与主动提醒。

- 账号保存与切换使用可报告错误的原子写入，区分凭据切换失败和切换后的历史保存失败；损坏快照不再被静默覆盖。
- 首页使用“用量记录数”“费用合计”“近 7 天”，展示估算依据、未计价记录和时间未分配量。菜单栏费用带估算标记。
- 本地统计、搜索、详情与官方配额使用独立刷新流程，筛选变化后丢弃过期结果。
- 数据健康窗口展示各来源扫描状态、最近成功时间、耗时、记录变化、解析/读取异常及 Activity 能力；支持脱敏诊断导出。
- 项目页按可靠工作目录识别 Git/worktree，支持名称、目录和会话归属调整。提供 Token 分解、趋势、Agent/模型分布、主要会话及预算状态。
- 项目历史补全只读取明确的工作目录元数据，不重复计入 Token。无法证明归属的历史保留为“未归属”。
- 独立会话详情增加执行时间线、结果/类型/证据筛选和稳定分页；只在有证据时按 turn 或父调用分组。
- 全局和项目可设置 Token 或估算美元预算，支持自然日、自然周、自然月及 80%/90%/100% 提醒。
- 官方配额使用实际抓取时间采样；样本不足或过期时不预测。预测仅按近期速度估算，不自动切换账号。
- 应用内提醒始终可用，系统通知需要主动开启；通知文本不含项目名或账号，周期与阈值去重状态保存在本地。
- 异常解释比较过去 14 天同一时刻，至少 7 个有效历史日；显示项目、Agent、模型变化贡献与统计限制，不将高消耗判定为浪费。
- 自动生成最近一个完整自然周的本地周报，保存数据和规则版本快照，可手动重新生成；支持 Markdown 周报和 CSV/JSON 数据导出。
- 导出默认脱敏、按后台分页读取，不受界面列表上限限制；可取消，写入失败不留下不完整目标文件。

升级将数据库从 v4 迁移至 v5。迁移前通过 SQLite 备份 API 创建一致性备份，原用量和会话历史保留。旧版本不能直接打开 v5 数据库；回退请使用升级前备份，并另外保存升级后的数据库。

不包含：新 Agent、云同步、团队功能、AI 生成分析、自动账号切换、实际订阅账单管理、历史价格系统、Keychain 迁移或公证工程。默认不扩大公开统计上传字段。

## English

Local-first usage confidence, project insights, and proactive alerts.

- Account persistence reports encoding, permissions, write, replacement, and verification failures. Corrupt snapshots are preserved; post-switch history failures are reported separately.
- Usage records are distinguished from requests, estimated costs from subscription bills, and the last seven days from calendar weeks.
- Local statistics, search, details, and official quota refreshes run independently and reject stale UI results.
- A dedicated data health window exposes scan freshness, duration, record changes, parsing/read diagnostics, and activity capabilities, with redacted diagnostic export.
- Projects use evidenced working directories and Git/worktree identity, with editable names and directory/session assignments. Views include token breakdowns, trends, agent/model distribution, sessions, and budgets.
- Background project metadata backfill preserves the token ledger. Unverifiable historical ownership remains unassigned.
- Session details now include a paginated execution timeline with result, event-kind, and confidence filters. Grouping requires explicit turn or parent-call evidence.
- Global and project budgets support tokens or estimated USD per calendar day, week, or month, with 80/90/100 percent thresholds.
- Official quota forecasts require fresh, sufficiently spaced observations from the same quota cycle. Cache reads do not create artificial new samples.
- In-app risk indicators are available without notification permission. System notifications are opt-in, redacted, and deduplicated locally.
- Deterministic anomaly explanations compare the same time of day over the preceding fourteen days, require seven valid samples, and expose independent contribution breakdowns and coverage limits.
- Local calendar-week reports are immutable snapshots until explicitly regenerated. Reports export as Markdown; usage, sessions, activity metadata, totals, and health export as CSV/JSON.
- Exports are redacted by default, paginated independently of UI limits, cancellable, and atomically published to the chosen destination.

The database migrates from schema v4 to v5 with a consistent SQLite backup. Original usage and session history are retained. Older binaries must use a pre-upgrade backup rather than opening the v5 database. Preserve a separate copy of post-upgrade data before rolling back.

No new agents, cloud sync, team features, model-generated analysis, automatic account switching, subscription billing management, historical price engine, Keychain migration, or notarization changes are included. Public publishing retains its existing allowlist.

# Kimi 配额与窗口拖动验收（2026-08-27）

基线：`1524589`；修复分支：`codex/fix-kimi-window-drag`。

## 行为与原因

- Kimi 只读现有 access token，不调用 token 刷新端点，不改写、备份或恢复登录凭据。有效 access token 不要求存在 refresh token。
- 读取根目录支持 `KIMI_CODE_HOME`，默认 `~/.kimi-code`。缺失/空值/格式错误/过期/接口失败分别返回可解释的状态；401不直接要求重新登录。
- 凭据文件变化使下一次配额查询重新尝试，仍遵守429和 Retry-After；只缓存文件元数据，不缓存令牌。最后成功配额超过24小时后降级本地估算。
- 原始拖动初始化只在脚本加载时检查一次桥接。现在同时处理已就绪与 `pywebviewready`，只注册一次。
- 拖动使用指针捕获，以抬起、取消、捕获丢失、失焦或隐藏结束；忽略旧手势迟到的坐标，只允许一个移动调用在途，后续位置合并为最新值。
- 真实 WKWebView 自动化事件曾报告 `buttons=0`，因此不使用该位掩码提前结束已开始的手势；回归覆盖这种事件。

# 刘海左侧用量圆环

在设置 → 刘海圆环，或原有状态栏菜单 → 显示／隐藏刘海圆环中启用。默认关闭，默认顺序为 Codex、Claude，可选择其他已配置的配额工具；至少保留一个工具。

圆环位于内置刘海屏左侧，直径 22 pt、间距 6 pt，距刘海约 8 pt。悬停 250 ms 显示数值，点击打开配额与今日小时趋势。点击同一圆环、外部区域、关闭按钮或 Esc 收起；点击另一圆环切换工具。查看卡片不激活 App、不获取键盘焦点。

## 数据与系统边界

- 圆弧默认代表剩余额度，设置可切换已使用额度；采用官方已用比例最高（剩余最少）的窗口，悬停明确显示方向、窗口和官方来源。颜色仍按已用比例判断紧张程度。只接受 0–100 的有效官方百分比，不用本地 Token 预算推算订阅额度；未知为空环，真实剩余零值保留为 0%，陈旧官方值标记 `~` 并显示文字说明。
- 今日统计使用独立连接、固定 `day` 范围和同一个数据库读取事务，不改变主面板筛选。小时趋势保留空缺，并说明跨小时观察区间与无法确定日期的历史用量。自定义配额 ID 映射到对应工具；工具与配额 ID 不同时，卡片明确标注工具汇总，趋势不冒充模型配额明细。
- 关闭卡片取消后续刷新、移除事件监听和临时 Esc 热键，丢弃晚到结果。悬停不查询数据库或网络；圆环订阅已有状态，没有动画定时器。启用期间每秒检查一次系统窗口几何，用于捕获同应用内的全屏变化。
- 使用 `NSScreen` 刘海区域定位；使用系统当前展示选项和公开窗口几何识别全屏，不读取其他应用窗口标题或内容。全屏、休眠、非活动会话和自己的原生菜单展开时收起。
- 无内置刘海屏、显示区域不足时仅保留原状态栏入口。长应用菜单可能与固定圆环重叠，可手动隐藏；无需新增辅助功能、输入监控或屏幕录制授权。
- 偏好仅存 App 的 UserDefaults：`tt.app.notchHUD.enabled`、`tt.app.notchHUD.providers`、`tt.app.notchHUD.quotaDisplay`。不进入共享 settings.json，不修改数据库契约或公开统计。

## 开发验收

初轮使用独立 `TokenTracker Dev.app`，`TT_UI_PREVIEW=1` 配合虚构数据库。`TT_UI_TEST_HUD_ONLY=1` 仅在预览模式中阻止启动／重开时自动弹主窗口，便于测试后台浮层。`TT_DEBUG_NOTCH=1` 输出几何、展开／关闭事件与前台进程 ID，不输出用量内容或凭据。

随后用户明确授权真实数据验证：取消预览和数据库／配额覆盖，正常扫描本地日志、读取当前登录账号的官方配额。`TOKENTRACKER_SETTINGS` 可指定独立 App 设置副本，本次仅在该副本中关闭公开上传，保留原设置。官方百分比与今日 Token／小时趋势已在实际卡片中核对；历史无法确定时间的数据仍单独提示，不归入今天。

真实补扫还修复了两个问题：官方配额先发布到界面，历史采样遇到扫描写锁时限时跳过、下次刷新重试；调用完成查询改为优先遍历最新 rowid，避免每次遍历整份 Agent 历史，Swift/Python 保持相同语义。两项修正均不修改数据库结构或统计口径，新增锁竞争与跨 Agent 重复调用 ID 回归测试。

真实数据修正后，59 项相关 Swift 测试（含 App、Activity、Codex 和差分验证）及 16 项 Python Activity 测试通过。扫描遗留的来源警告为无法确定时间的历史数据；本次读取／解析错误均为零，未知历史未计入今日用量。

## 2026-10-15：与 CC Switch 对照配额口径

已核验本机 CC Switch 4.0.10，对应源码 tag `v4.0.10`（commit `90fb37ffb76bf06f2d021cd020b7f677216e916c`）。其 [订阅配额服务](https://github.com/farion1231/cc-switch/blob/v4.0.10/src-tauri/src/services/subscription.rs) 使用当前 CLI 登录态及官方接口；[显示规则](https://github.com/farion1231/cc-switch/blob/v4.0.10/src/components/quota/quotaRules.ts) 默认显示 `100 - utilization` 的剩余额度。用户已选择与其一致的剩余方向，设置仍可切换已用。

真实问题与修正：

- 此前圆环只有百分比，缺少已用／剩余文字；现在悬停和无障碍名称显示方向，详情显示全部窗口和官方数据获取时间。
- 本机 Claude Code 钥匙串 OAuth 为空壳且没有当前凭据文件，但旧逻辑继续使用本地备用登录态查询得到 0%。App 现在启用 `OfficialQuotaService(currentLoginOnly: true)`，只取当前有效钥匙串（优先）或凭据文件，不跨到备用登录态或没有账号归属的桌面样本。按当前凭据指纹隔离缓存，退出或切换登录后不能沿用前账号的官方结果。兼容 CLI 默认调用策略不变，不修改登录态。
- 官方接口缺少某个窗口或查询失败时，圆环把该窗口标记暂无数据，本地 Token 预算百分比不能参与最紧窗口选择。旧缓存依然存在但不会被当前登录策略使用，无需删除真实缓存或数据库。

独立核对：当次 Codex 当前桌面会话官方查询已用 88%、周已用 14%，与当时 TokenTracker 官方结果相同；剩余应为 12%／86%，验证时须考虑查询时间差。今天 00:00 至 15:45（Asia/Shanghai，左闭右开）两个本地库中 Claude 611 条记录的四项 Token 完全一致；Codex 511 条记录在将 CC Switch 缓存包含输入转换为非缓存输入后也完全一致。本轮未修改 Token 扫描器、去重、数据库 schema、费用和公开统计字段。

本轮验收结果：59 项唯一 Swift 测试通过（24 项 App、7 项 Claude 配额、28 项缓存／重试／菜单栏格式化）；`--development` release 构建、包签名检查、中英文资源检查与 `git diff --check` 通过。实际 UI 已验证设置默认选择剩余额度；Codex 圆环和详情显示 5 小时剩余 96%、周剩余 99% 与 16:09:44 获取时间，同次当前 CLI 官方缓存为已用 4%／1%，重置时间与桌面独立查询一致；稍后的独立查询已用增长为 5%／1%，不得混淆不同获取时间。Claude 灰色空环与详情均为暂无数据，显示当前登录态缺失原因，本地今日 Token 仍可单独查看。Esc 关闭已通过。独立开发 App 使用关闭公开上传的设置副本运行，未替换系统安装包、未提交／推送／发布。
